# 機能

QvReader が今日できること、そして意図的にしないことを、簡潔かつ正直に説明します。

## 製品ポジション

QvReader は、**軽量・高速・ドキュメント中心の Markdown リーダー**で、ちょうど十分な編集機能を備えます。
「README / AI 生成ドキュメント / ローカルメモを素早く読む」瞬間を狙います——開いて、ウェブページのように
読み、必要ならその場で編集し、`Esc` で閉じる。**IDE** でも、ナレッジベースでも、クラウド同期の
ボールトでも、完全な CMS でもありません。

中核となる価値（プロジェクト憲章より）：

1. 開くのが速く、インストールが小さい。
2. クリーンな読書面、余計なものがない。
3. 読書がデフォルト。編集は明示的で、ソースを誤って変更できない。
4. 編集は本当の修正に十分な程度であり、重いエディターにはしない。
5. ローカルファイル・ローカル優先。必須のアカウントやクラウドはない。

## 現在の能力（v0.1.0）

- CommonMark / GFM ドキュメントの**即時読み込み**。
- **忠実性** —— ソースファイルが唯一の真実。未知の構文・改行・エンコーディングはそのまま保持。
- **F2 インライン編集**と **F3 分割編集**、ライブプレビュー付き。
- **コードハイライト**（highlight.js）、**数式**（KaTeX）。
- **TOC アウトライン**、ファイルツリー付き**フォルダワークスペース**。
- **テーマ**、調整可能な文字サイズ、**6 つの UI 言語**。
- **CLI**（`qvreader <ファイル>` / `qvreader .`）。

## クロスプラットフォーム

| プラットフォーム | 状態 |
|---|---|
| macOS（Apple Silicon + Intel、universal） | 主要・サポート対象 |
| Windows（x64） | CI 経由でサポート |
| Linux（Debian / AppImage） | コア安定後に評価 |

## 明確にスコープ外

プロジェクト憲章は「速く・小さく・集中」というアイデンティティを守るため、以下を除外します：

- クラウド同期、Git ホスティング同期、内蔵ドライブ。
- ブログ公開、WeChat 記事レイアウト、汎用 CMS。
- Typora、Obsidian、VS Code に合わせるナレッジベース / IDE 化。
- アカウント、支払い、アクティベーションコード、サブスクリプション、複数デバイスライセンス。
- デフォルトのファイル関連付けの強制・静かな設定。
- 巨大で未検証のプラグイン・テーマエコシステム。
