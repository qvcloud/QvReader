# ロードマップ

QvReader が計画していること、そして意図的に作らないことを透明に示します。
アイテムは、仕様化され、起動速度・バイナリサイズ・Markdown 忠実性・中核の読書体験を損なわないと
示された後でのみ開発に入ります。

## 高優先度の候補

- **大規模ドキュメントのパフォーマンス基準** —— 量化的な読み込み・スクロール目標（単に「開く」だけでなく）。
- **外部ファイルのライブリフレッシュ** —— 別のエディター / AI エージェントがファイルを書き換えたとき、データ損失なく更新。
- **ソース ↔ プレビューのブロック連動ハイライト** —— 単純な同期スクロールより細かい。
- **macOS ネイティブの磨き込み** —— ファイル関連付け UX、メニュー、各プラットフォームのショートカット。

## 二次 / 後で評価

- ネイティブ **PDF エクスポート**、単一ファイル **HTML エクスポート**。
- **Mermaid** 図とよりリッチな**数式**を、任意・遅延ロードの拡張として。
- **Linux** サポート —— コア機能が安定しテスト体制ができてから。
- ポータブル（グリーン）Windows ビルド。
- Markdown 認識のテーブルフォーカス / フルスクリーン読書。

## 明確にスコープ外

憲章が境界を定めます。QvReader は「何でも屋」を追いません：

- クラウド同期 / 内蔵ドライブ / Git ホスティング同期。
- ブログや CMS 公開。
- アカウント、支払い、アクティベーション、ライセンス、コンテンツを読むテレメトリー。
- デフォルトのファイル関連付けを静かに設定すること。
- Typora / Obsidian / フル IDE との機能対等の競争。

ロードマップの各アイテムは仕様プロセスのレビュー質問にゲートされます：それは現実の頻繁なシナリオに
役立つか？「速く開き、よく読み、邪魔しない」を守るか？サイズ / 起動 / メモリへの測定可能な影響は？
ソース形式に触れるか？プラットフォーム同等の操作は？ネットワーク / アカウント / 支払い / プライバシーに関わるか？

候補作業は [issue トラッカー](https://github.com/qvcloud/QvReader/issues) で議論されます。
