# 路线图

对 QvReader 正在规划、以及刻意不做的内容，提供透明的视图。
只有经过规格化、并被证明不损害启动速度、包体大小、Markdown 保真或核心阅读体验的功能，才会进入开发。

## 高优先级候选

- **大文档性能基线** —— 量化的加载与滚动目标，而不只是"能打开"。
- **外部文件实时刷新** —— 当其他编辑器 / AI 代理改写文件时，无数据丢失地更新。
- **源码 ↔ 预览块级联动高亮** —— 比纯同步滚动更精细。
- **macOS 原生打磨** —— 文件关联交互、菜单、各平台快捷键。

## 次要 / 稍后评估

- 原生 **PDF 导出**、单文件 **HTML 导出**。
- **Mermaid** 图表与更丰富的**数学公式**作为可选、懒加载的扩展。
- **Linux** 支持 —— 仅在核心功能稳定且具备测试能力之后。
- 便携（绿色）Windows 构建。
- 感知 Markdown 的表格聚焦 / 全屏阅读。

## 明确排除的功能

宪章划定边界。QvReader 不去追逐"包罗万象"：

- 云同步 / 内置网盘 / Git 托管同步。
- 博客或 CMS 发布。
- 账号、支付、激活、授权，或读取你内容的遥测。
- 静默设置默认文件关联。
- 与 Typora / Obsidian / 完整 IDE 进行功能对齐竞赛。

路线图上的每一项都受规格流程中评审问题的约束：它是否服务于真实、高频的场景？
是否守护"打开快、阅读好、不打扰"？它对体积 / 启动 / 内存的可衡量影响是什么？
它是否触及源格式？各平台的等价交互是什么？是否涉及网络 / 账号 / 支付 / 隐私？

候选工作在 [issue 追踪器](https://github.com/qvcloud/QvReader/issues) 中讨论。
