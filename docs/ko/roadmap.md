# 로드맵

QvReader가 계획하는 것과 의도적으로 만들지 않는 것을 투명하게 보여줍니다.
항목은 명세화되고, 시작 속도·바이너리 크기·Markdown 충실성·핵심 읽기 경험을 해치지 않는다는 것이
입증된 후에만 개발에 들어갑니다.

## 우선순위 높은 후보

- **대형 문서 성능 기준** — 정량화된 로드·스크롤 목표(단지 "열린다"가 아니라).
- **외부 파일 라이브 새로고침** — 다른 에디터 / AI 에이전트가 파일을 다시 쓸 때 데이터 손실 없이 업데이트.
- **소스 ↔ 미리보기 블록 연동 강조** — 단순 동기화 스크롤보다 세밀함.
- **macOS 네이티브 다듬기** — 파일 연결 UX, 메뉴, 플랫폼별 단축키.

## 2차 / 나중에 평가

- 네이티브 **PDF 내보내기**, 단일 파일 **HTML 내보내기**.
- **Mermaid** 다이어그램과 더 풍부한 **수식**을 선택·지연 로드 확장으로.
- **Linux** 지원 — 핵심 기능이 안정되고 테스트 역량이 갖춰진 후.
- 휴대용("그린") Windows 빌드.
- Markdown 인식 테이블 포커스 / 전체 화면 읽기.

## 명시적으로 범위 제외

헌장이 경계를 정합니다. QvReader는 "모든 것이 되기"를 쫓지 않습니다:

- 클라우드 동기화 / 내장 드라이브 / Git 호스팅 동기화.
- 블로그 또는 CMS 게시.
- 콘텐츠를 읽는 계정, 결제, 활성화, 라이선스, 원격 측정.
- 기본 파일 연결을 조용히 설정.
- Typora / Obsidian / 전체 IDE와의 기능 동등 경쟁.

로드맵의 각 항목은 명세 프로세스의 검토 질문에 의해 게이트됩니다: 실제 자주 일어나는 시나리오에
도움이 되는가? "빨리 열고, 잘 읽고, 방해하지 않기"를 지키는가? 크기/시작/메모리에 미치는 측정 가능한
영향은? 소스 형식을 건드리는가? 플랫폼별 동등 상호작용은? 네트워크/계정/결제/개인정보와 관련되는가?

후보 작업은 [이슈 트래커](https://github.com/qvcloud/QvReader/issues)에서 논의됩니다.
